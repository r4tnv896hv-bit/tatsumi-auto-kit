# short-clip（長い動画 → 切り抜きショート）

ご本人の長い動画から、縦長のショート動画を作るスキルです。
投稿・アップロード・送信は一切しません。できあがるのはパソコンの中のファイルだけです。

使う人はエンジニアではない方です。専門用語を使わず、短い文で話しかけてください。

---

## 最初に必ず確かめること（ここで止まる）

```
1 その動画は「ご本人が作った」or「切り抜きの許可をもらった」ものですか？
   → どちらでもなければ、作りません。理由を短く伝えて終わります。
2 動画ファイルの場所（例: /Users/名前/Movies/live0101.mp4）
3 字幕(.srt)はありますか？（無ければ文字起こしを試します）
4 縦にする方法: 「ぼかし背景」（初期値・全体が見える）or「真ん中切り抜き」（人が中央の動画向け）
```

答えが来るまで先に進みません。

---

## 全体の流れ

```
1 文字起こし     scripts/transcribe.py
2 候補さがし     scripts/find_segments.py  → segments.json の下書き
3 Claude が選ぶ  segments.json を読んで直す（下の「選び方」）→ ご本人に見せてOKをもらう
4 作る＋点検     scripts/make_clips.py      → clip01_vertical.mp4 …
5 渡す           完成ファイル・長さ・最初の2秒の言葉・ご本人が確かめること
```

スクリプトの場所は、このファイルと同じフォルダの `scripts/` です。
以下 `$S` はその絶対パスのことです（例: `/Users/名前/…/short-clip/scripts`）。
パスは必ず絶対パスで書きます。

### 1 文字起こし

```bash
python3 $S/transcribe.py /絶対パス/動画.mp4
```

- 終了コード 0 → 動画の隣に `動画.srt` ができる
- 終了コード 2 → whisper が入っていない。画面の案内どおり、ご本人に .srt を用意してもらう
  （自分の YouTube 動画なら YouTube Studio の自動字幕を .srt で落とせます）
- 文字起こしは誤字があります。固有名詞・数字・商品名は、ご本人に確かめてもらいます。
  直すときは .srt をそのまま直してください（字幕にそのまま出ます）。

### 2 候補さがし

```bash
python3 $S/find_segments.py /絶対パス/動画.mp4 /絶対パス/動画.srt --count 5 --mode blur \
  --out /絶対パス/作業フォルダ/segments.json
```

30〜60秒・文の頭から文の終わりまで・最初の言葉に「つかみ」がある範囲を、点数順に出します。
これは機械の下書きです。そのまま使わず、次の「選び方」で Claude が見直します。

### 3 選び方（Claude がやること）

.srt を全部読み、segments.json を直します。

```
□ 最初の2秒で「続きを見たくなる言葉」が出るか
   （問いかけ・意外な結論・数字・「やってはいけない」など）
   → 弱ければ、後ろの強い一言を parts の1つめに持ってきてもよい（下の例）
□ その1本だけ見ても意味が通じるか（「さっき言ったように」で始まらない）
□ 文の途中で終わっていないか
□ 30〜60秒か（parts の合計）
□ 間違った情報・言い過ぎ・誰かを傷つける発言が入っていないか
□ title（画面上部の見出し）を 15文字以内で付ける
```

parts は「元動画の何秒から何秒まで」の組です。2つ以上書くと、その順につなぎます。

```json
{"id": "clip02", "title": "9割が見落とす出費",
 "parts": [[49.88, 68.95], [106.63, 119.45]]}
```

秒数は .srt の時刻を見て決めます。言葉の頭の 0.1〜0.2秒前から、言い終わりの 0.3秒後までにすると
声が切れません。
直したら、候補の一覧（何秒〜何秒・つかみの言葉・見出し）をご本人に見せて、OKをもらいます。

### 4 作る＋点検

```bash
python3 $S/make_clips.py /絶対パス/作業フォルダ/segments.json --outdir /絶対パス/出力フォルダ
echo $?
```

1本ずつ、次を自動でやります。

```
切り出し   parts ごとに頭出しして作り直す（長さは 30fps のコマ数ちょうど）
縦長       1080x1920（ぼかし背景 or 真ん中切り抜き）
字幕       .srt の言葉を、太いヒラギノ・1行12文字・2行まで で焼き付け
           下 420px と 上 250px はボタンや名前に隠れるので空ける
つなぐ     concat demuxer で無劣化につなぐ
情報消し   作成日時・エンコーダ名・x264 の署名などを消す
点検       全体・映像・音声 の3つの長さが、予定と ±0.5秒 以内か／1080x1920か／情報が残っていないか
```

終了コードが 0 なら全部合格。3 なら不合格があり、そのファイルは `_NG.mp4` に名前が変わります。
**`_NG` のファイルは渡しません。** 画面の点検結果（全文）を見て直します。

### 5 渡す

次をまとめて伝えます。

```
- できたファイルの絶対パスと長さ（点検の数字。測った時刻も添える）
- 各クリップの「最初の2秒に話している言葉」
- ご本人に確かめてほしいこと:
   字幕の誤字（特に固有名詞・数字）／言い過ぎや事実の間違いがないか／
   映っている人・BGM・画像の権利に問題がないか
```

## 長さがずれる事故について（必ず守る）

過去に「47秒のはずの切り抜きが 4分14秒 のファイルになった」事故がありました。
1本のフィルタの中で trim と concat を組み合わせたため、元動画のコマ数（23.976fps など）によって、
音声が終わったあとも止まった映像が何分も続いたのが原因です。

```
× やらない  1つの -filter_complex で trim → concat
○ やる      parts ごとに -ss / -t で別ファイルに作り直す → concat demuxer でつなぐ
○ やる      完成後に「全体・映像・音声」の3つの長さを測る（make_clips.py が自動でやる）
```

自分で ffmpeg を手で打って作り直したときも、最後に必ず点検してください。

```bash
python3 -c "import sys; sys.path.insert(0,'$S'); import vidutil as v; v.verify('/絶対パス/out.mp4', 予定秒数)"
```

## うまくいかないとき

```
ffmpeg が見つからない     → README の「準備」。または FFMPEG=/絶対パス/ffmpeg を付けて実行
字幕が豆腐(□)になる       → ヒラギノが無い環境。vidutil.py の jp_font() に日本語フォントのパスを足す
候補が3本未満             → --min 25 に下げる／parts を2つつなぐ／元動画が短すぎないか確認
不合格(_NG)が出た         → エラー全文を要約せずにご本人（またはサポート）に見せる
```
