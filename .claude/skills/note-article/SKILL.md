# note-article（note記事の下書きスキル）

note に載せる記事の「下書き」を作るスキルです。
公開・投稿・送信は一切しません。できあがるのはパソコンの中のファイルだけです。

使う人は、エンジニアではない副業の初心者を想定しています。
専門用語を使わず、短い文で話しかけてください。

---

## 全体の流れ（この順で、1段ずつ進める）

```
1 聞き取り        テーマ・読者・ゴールを聞く（答えが来るまで先に進まない）
2 題名5案         数字入りの題名を5つ出し、1つ選んでもらう
3 構成            大見出し（H2）5〜7個の骨組みを出し、OKをもらう
4 本文            約8,000字の下書きを短い行で書く（図の指示つき）
5 販売文          有料部分の手前に置く「ここから先で分かること」を書く
6 自己チェック    check_draft.py と目視の点検表で確かめ、直す
7 渡す            できたファイルと「ご自身で確かめること」の一覧を伝える
```

各段の終わりで、必ず使う人に確認を取ってから次へ進みます。
勝手に全部を一気に書き上げないでください（途中で方向がずれると全部書き直しになるため）。

書き方の決まりは `rules.md` にまとめてあります。本文を書く前に必ず読んでください。
できあがりの見本は、キットの `samples/note/sample_output.md` にあります（あれば参考にする）。

このスキルのフォルダの中身：

```
SKILL.md                  この手順書
rules.md                  書き方の決まり
self_check.md             目視の点検表
templates/hearing.md      聞き取りの質問
templates/title_outline.md 題名5案と構成の形
templates/sales_copy.md   販売文の形
templates/work_memo.md    作業メモの形
templates/profile.md      書き手の声（口ぐせ・読者・使わない言葉）。作業フォルダの note/profile.md にコピーして使う
scripts/check_draft.py    機械の検査（Python 3、追加インストール不要）
```

---

## 0 書き手の声（最初の1回）

作業フォルダ（CLAUDE.md の絶対パス。初期値 `~/kit-work`）の `note/profile.md` があれば、毎回最初に読みます。
無ければ `templates/profile.md` をコピーして、【】をご本人と埋めます（【】が3つ以上残っていたら、書く前にまとめて聞く）。
SNS 用の `sns/voice_profile.md` がある場合は、口ぐせ・使わない言葉をそろえます。

## 1 聞き取り

`templates/hearing.md` の質問を、そのまま1回のメッセージで聞きます。
必ず聞くのは次の3つです。

- テーマ：何について書くか
- 読者：誰に読んでほしいか（年代・仕事・いまの悩み）
- ゴール：読み終えた人に何ができるようになってほしいか

任意で聞くもの（答えが無くても進めてよい）：

- ご自身の体験や実績（数字があれば、いつの・何の数字か）
- 無料記事か、有料記事か（有料なら、どこから有料にしたいか）
- 文の調子（です・ます／くだけた話し言葉）

答えがあいまいなときは、1回だけ聞き直します。
それでもあいまいなら、こちらで仮に決めて「仮にこう決めました」と書いてから進めます。

**ご本人の体験・数字を、こちらで作らないでください。**
体験が無い場合は「体験談なし」で書ける構成にします。

## 2 題名5案

`templates/title_outline.md` の「題名」の形で、5案を出します。

- 5案すべてに数字を入れる（例：「5つの手順」「7つの失敗」「30分」）
- 数字は「数えられるもの」にする（手順の数・項目の数・時間）
- 収入の金額や「◯万円稼げる」は題名に入れない
- 題名の数字と、本文の中身の数を必ず合わせる（「7つ」なら本文も7つ）
- 前半＝テーマ、後半＝読むと分かること、の形を基本にする
- 「必見」「今すぐ」などの飾りの言葉は付けない

5案それぞれに、ねらい（なぜこの言い方か）を1行添えます。
使う人に番号で選んでもらいます。混ぜたい・直したいと言われたら合わせます。

## 3 構成

`templates/title_outline.md` の「構成」の形で出します。

- 大見出し（H2）は5〜7個。各H2の下に小見出し（H3）を2〜4個
- 各H2に「ここで読者が分かること」を1行
- 各H2の目安の字数（全体で約8,000字になるように配分）
- 図を入れる場所（全体で4〜7枚）
- 有料記事なら、有料ラインを置く場所（「どこまで無料で読めるか」）

OKが出るまで本文に進みません。

## 4 本文（約8,000字）

`rules.md` の決まりで書きます。要点だけ書くと次のとおりです。

- 空白を除いて 7,000〜9,000字（目安8,000字）。水増しはしない
  （使う人が字数を指定したときは、そちらに従う。その場合 check_draft.py の字数のNGは無視してよいと伝える）
- 1行は20〜25字くらいで改行。1段落は3行まで（スマホで読む前提）
- 表は使わない。比べるものも見出し＋箇条書きで書く
- 本文に出典・参考URLを書かない。出どころは作業メモにだけ書く
- 確かめられない数字は書かない。書くなら「要確認」の印を付ける
- 稼げることを約束する言い方をしない

図を入れる場所には、次の形の「図の指示」を置きます。

```
［図1］ここに図を入れる
図の題：〇〇の3ステップ
図の説明：左から右へ3つの箱。①〜 ②〜 ③〜。箱の間は矢印。字は大きく、1枚に言いたいことは1つ。
```

図そのものは作りません。使う人が自分で作るか、別の道具で作ります。

有料記事の場合は、有料ラインの所に次の2行を置きます。
目印の行は **必ず `=== ここから有料 ===` の1行だけ** にします（sns-to-note・sns-post・check_draft.py がこの行で無料部分と有料部分を分けるため。ほかの書き方にしない）。
（noteに貼ったあと、使う人がこの行を消して、noteの「有料エリア」の線を同じ位置に引きます）

```
<!-- 販売文（sales_copy.md）をここに入れる -->

=== ここから有料 ===
```

手順を書く項目は、最後に次の形でまとめます（rules.md 3節）。

```
・時間：30分×1回
・道具：〇〇
・確かめ方：〇〇ができている

つまずく所：
（2〜3行）
```

**字数は、書き終えたら必ず測ります。**
短い行で書くと、思ったより字数が増えません（見本づくりでは、1回目が約4,400字でした）。
足りないときは、前置きや繰り返しで埋めず、次のどれかを足します。

- その項目の「例」（読者の3行の例、見出しの例、書き出しの例）
- 「確かめ方」「つまずく所」の具体化
- 構成で字数が少なかった見出しへの小見出しの追加（題名の数字が変わらない所だけ）

事実の確認が要る所には、本文の中に `【要確認：何を確かめるか】` を残します。
（例：noteの手数料、ツールの料金、法律や税金の話）
この印は、使う人が確かめて消すためのものです。勝手に消さないでください。

書き終えたら、次の3つのファイルに保存します。

```
<作業フォルダ>/note/（日付）_（短い名前）/
  article.md     題名・本文・図の指示
  sales_copy.md  販売文（5で作る）
  work_memo.md   作業メモ（出どころ・判断・要確認の一覧）
```

作業フォルダは CLAUDE.md の「フォルダの地図」に書かれた絶対パス（初期値 `~/kit-work`）です。書かれていなければ、いま開いているフォルダの中に `note_drafts/` を作ります。
作業メモの形は `templates/work_memo.md` を使います。

## 5 販売文（有料部分の手前の文）

`templates/sales_copy.md` の形で書きます。

- 無料部分の最後、有料ラインの直前に置く文
- 「この先で何が分かるか」を箇条書きで5〜7個（本文の見出しと一致させる）
- 「こんな人に向いています／向いていません」を両方書く
- 収入の約束・「必ず」「誰でも」「最短」・期限で急かす言い方はしない
- 300〜600字

無料記事の場合も、「次に読んでほしい記事への案内文」として同じ形で作れます。

## 6 自己チェック

順番に2つ行います。

1. 機械の検査：Python が使えるなら次を実行する

   ```
   python3 （このスキルのフォルダ）/scripts/check_draft.py <作業フォルダ>/note/（作ったフォルダ）/article.md
   ```

   字数・禁止の言い方・URL・表の記号・長すぎる行・4行以上の段落・図の数・要確認の数が出ます。
   「NG」が出た項目は直してから、もう一度実行します（NGが0件になるまで）。
   「注意」は目で見て、問題なければそのままでかまいません。
   本文の中で「〇〇という言い方はしない」と説明するときも、禁止の言葉そのものは書かずに言い換えます
   （検査はそこも数えます）。
   Python が無い環境なら、同じ項目を自分で数えて結果を書きます。

2. 目視の点検：`self_check.md` の項目を1つずつ見て、結果（OK／直した／要確認）を書きます。
   特に次の4つは必ず見ます。
   - 確かめられない数字が無いか
   - 稼げることの約束が無いか
   - 他の人の記事・本・動画の文章をそのまま写していないか
   - 出どころが本文ではなく作業メモに書いてあるか

チェックの結果は `work_memo.md` の最後に貼ります。

## 7 渡す

最後に、使う人へ次を短く伝えます。

- 作ったファイルの場所（3つ）
- 題名・字数（空白を除く）・図の数
- `【要確認】` の数と、その一覧
- 次の一文を必ず入れる：

> この下書きは、事実や数字をAIが確かめたものではありません。
> 公開する前に、要確認の印の付いた所と、数字・料金・ルールの話を
> 必ずご自身で公式の情報と照らして確かめてください。
> ご自身の体験の部分は、ご自身の言葉に書き直すと読まれやすくなります。

**公開・投稿・送信はしません。** 「noteに投稿して」と言われても、
このスキルの中では行わず、ご本人がnoteの画面で貼り付けて投稿する手順を案内します。

---

## してはいけないこと（このスキルの中で）

- 使う人の体験・実績・数字・お客様の声を作る
- 確かめていない数字を、確かな事実のように書く
- 「月◯万円稼げる」「必ず」「誰でも」などの約束・あおり
- 他の人の記事や本の文章を写す（言い換えて丸写しも含む）
- 本文に出典やURLを並べる（出どころは作業メモへ）
- note・SNSへの投稿、メール送信、ファイルのアップロード
